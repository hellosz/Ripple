## ADDED Requirements

### Requirement: 文本层级色满足可读性
系统 SHALL 提供语义化的文本颜色层级（主文本、次级文本、弱化文本），并确保次级文本与弱化文本在深色背景上满足 WCAG AA 对比度要求。

#### Scenario: 次级文本可读
- **WHEN** 页面渲染作者名、标签、元信息、结果计数等次级文本
- **THEN** 这些文本使用满足对比度要求的次级色，而非低于 50% 不透明度的低对比灰紫

#### Scenario: 主文本保持高对比
- **WHEN** 页面渲染标题、正文描述、按钮主文案
- **THEN** 主文本使用接近前景色（--foreground）的高对比色

### Requirement: 卡片具有视觉层次
系统 SHALL 让技能卡片通过阴影与边框在深色背景上形成可辨识的层次，而不是仅靠极淡边框区分。

#### Scenario: 卡片有柔和阴影
- **WHEN** 首页技能卡片网格渲染
- **THEN** 每张卡片带柔和阴影与明显边框，与背景形成可感知的层级

#### Scenario: 卡片悬停有反馈
- **WHEN** 用户悬停卡片
- **THEN** 卡片边框或表面色增强，提供可感知的交互反馈

### Requirement: 图标与操作入口对比清晰
系统 SHALL 让导航与工具栏图标、按钮文字使用满足对比度的颜色，并为主操作提供可辨识的视觉重量。

#### Scenario: 图标对比清晰
- **WHEN** 渲染详情页工具栏图标（波纹/收藏/下载/分享）与导航操作图标
- **THEN** 图标颜色清晰可见，且主操作与次操作有可感知的区别

### Requirement: 组件颜色来自设计 token
系统 SHALL 让组件颜色引用全局语义 token，而不是散落各处的任意颜色值，以保证视觉一致与可维护性。

#### Scenario: 颜色引用 token
- **WHEN** 组件需要指定文本、边框或表面颜色
- **THEN** 组件引用全局定义的语义 token（CSS 变量或 Tailwind 扩展色），而非硬编码 rgba 值
